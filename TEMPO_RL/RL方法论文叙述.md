# TEMPO-RL：多轮表格智能体的证据引导强化学习

## 1. 问题设定

表格问答智能体面临一个核心挑战：用户的问题往往涉及多张表格、需要多步计算，且以多轮对话的形式逐步深入。一个完整的对话包含 N 个子问题，每个子问题内部又有多步工具调用（加载表格、搜索、Python 计算等），子问题之间则通过一段压缩记忆（memory）传递已发现的关键信息。

SFT 训练能让模型学会基本的工具调用格式和回答范式，但存在两个根本局限：（1）SFT 只模仿行为，不区分"有效证据获取"和"无效工具调用"；（2）SFT 无法教会模型在子问题之间写什么样的记忆——记住什么、丢弃什么、如何忠实于原始观察而非编造。

强化学习提供了解决这些问题的自然框架。我们设计了一套**证据引导的奖励函数**和**分阶段课程训练策略**，在不依赖额外价值模型（critic）的前提下，逐步提升模型的工具使用效率、答案证据支撑度和跨轮记忆管理能力。

## 2. 奖励设计：证据作为桥梁

TEMPO-RL 的奖励函数将"证据"作为连接模型行为与训练信号的桥梁。核心思路是：benchmark 中的每个采分点（score point）对应一个预期发现的事实——称为**目标证据（Target Evidence）**。模型在工具调用过程中通过 observation、代码执行结果等途径逐步验证这些证据，由**证据账本（Evidence Ledger）**跟踪覆盖率变化。

### 2.1 目标证据构建

从 benchmark 样本中自动提取每个子问题对应的事实单元（EvidenceItem），包括原始数值（raw_value）、派生计算值（derived_value）和文本事实（text_fact）。提取先通过正则匹配数值、比例、时间等结构化信息，再通过 LLM 补全实体、指标、单位等语义标注。这种"规则先行、LLM 补充"的双策略设计保证了证据提取的覆盖率和准确性。

### 2.2 证据账本与验证

证据账本是一个单调递增的覆盖跟踪器：证据一旦被验证就不被移除，信用持续累积。工具调用产生的 observation 和代码输出被输入到六个维度的规则验证器：

- **值匹配（C_value）**：observation 中的数值是否与目标证据匹配（支持模糊匹配、单位换算）
- **来源匹配（C_source）**：observation 是否来自正确的表格/文件
- **绑定匹配（C_binding）**：实体、时间、指标是否与目标证据一致
- **派生验证（C_input, C_operator, C_result）**：对于计算结果，验证输入值、运算符和输出值

这些验证器全部基于规则，不调用 LLM——因为它们被高频调用（每步工具调用都要触发），LLM 的延迟和成本不可接受。

### 2.3 三分量奖励函数

奖励函数包含三个分量，分别针对工具使用、答案质量和记忆管理：

**工具奖励**——评估每一步工具调用的证据获取效率：

$$r_{tool} = \eta \cdot \max(0, \Delta\Phi) - \lambda_{call} - \lambda_{invalid} \cdot \mathbb{I}_{invalid} - \lambda_{repeat} \cdot \mathbb{I}_{repeat}$$

其中 $\Delta\Phi$ 是本步带来的证据覆盖率增量，后续项分别惩罚工具调用本身的开销、无效调用和重复调用。

**答案奖励**——评估最终答案的正确性和证据支撑：

$$r_{answer} = \frac{\sum w_c \cdot C_{correct} \cdot G}{\sum w_c} - \lambda_{format} \cdot \mathbb{I}_{format} - \lambda_{extra} \cdot N_{extra}$$

每个采分点 claim 需要同时满足两个条件才获得正向奖励：正确（$C_{correct}$，与标准答案一致）且可溯源（$G$，能在 observation、memory 或代码输出中找到支撑）。防止模型给出碰巧正确的"猜测"。

**记忆奖励**——评估模型生成的记忆质量：

$$r_{mem} = \alpha_f \cdot F_i + \alpha_s \cdot S_i - \lambda_{comp} \cdot P_{comp}$$

其中 $F_i$（忠实度）衡量记忆中的每一项是否能在原始 observation 中找到支撑，防止模型编造数据。$S_i$（未来依赖覆盖）衡量记忆是否保留了后续子问题需要的信息——通过分析子问题间的拓扑依赖关系（Future Dependency Coverage, FDC）来判定。$P_{comp}$ 对过长记忆施加压缩惩罚。

## 3. 训练方法：GRPO 风格的组相对策略优化

### 3.1 为什么不需要 Critic

传统的 actor-critic 方法需要训练一个独立的价值网络来估计状态价值，这带来额外的计算开销和训练不稳定性。我们采用 GRPO（Group Relative Policy Optimization）风格：每个子问题独立采样 K 条轨迹，同一 prompt 的 K 条轨迹构成一个对比组。Advantage 通过组内 z-score 归一化计算：

$$A = \frac{R - \mu_{group}}{\sigma_{group} + \varepsilon}$$

好轨迹的 return 自然高于组均值，获得正 advantage；差轨迹低于均值，获得负 advantage。不同 segment 类型（tool / answer / memory）分别在自己的组内归一化，避免 reward scale 差异互相污染。

### 3.2 分段 Token 级训练

一条完整对话被切分为多个 segment（工具步 × 多个 + 答案段 + 记忆段），每个 segment 携带对应的 return-to-go。工具段的 return-to-go 采用折扣累计形式：

$$G_{tool}[t] = \sum_{l=t}^{T-1} \gamma^{l-t} \cdot r_{tool}[l] + \kappa_{ans} \cdot \gamma^{T-t} \cdot r_{answer}$$

这样设计的动机是：早期工具步不仅为自己得分，还通过折扣因子承担了最终答案质量的"远期信用"。答案段和记忆段的 return 则直接使用各自的即时奖励。

在 token 级别，只有模型生成的 assistant 消息（tool_call、answer、memory）参与训练，system prompt、用户问题和工具返回结果被 mask。损失函数采用 PPO 风格的 clipped surrogate objective：

$$L = -\min(\rho \cdot A,\; clip(\rho, 1-\varepsilon, 1+\varepsilon) \cdot A)$$

其中 $\rho = \pi_\theta / \pi_{old}$ 是新旧策略在 token 级别的概率比，$\varepsilon$ 控制每次更新的幅度。

### 3.3 训练复用的设计选择

代码实现中 Phase 1 和 Phase 2 共用同一个 `SegmentGRPOTrainer`——GRPO 算法本身不随数据变化。这种设计避免了训练逻辑的重复实现，保证了所有阶段受益于相同的优化器调优和 bug 修复。

## 4. 分阶段课程训练

直接在一个阶段内同时优化工具使用、答案质量和记忆管理三项能力，信号会互相干扰。我们采用课程学习（curriculum learning）的策略，将训练分解为四个递进阶段。

### 4.1 Phase 0：奖励基础设施（离线，不需要 GPU）

Phase 0 不涉及任何模型训练，而是构建 RL 训练所需的全部先验知识：从 benchmark 中提取目标证据，分析子问题间的拓扑依赖关系，并通过离线审计脚本验证输出质量。

这一步的设计出发点是：RL 训练的质量高度依赖奖励信号的准确性。如果目标证据缺失或依赖关系错误，训练会把模型引向错误的方向。因此我们在训练前离线完成这些计算，并通过结构化校验（evidence item 类型完整性、derived evidence 的输入链、dependency 的时间方向正确性等）确保基础设施正确。

### 4.2 Phase 1：单子问题独立训练（工具 + 答案）

Phase 1 将每个子问题视为独立的优化单元，不引入跨子问题的记忆机制。模型在单轮对话中学习：收到问题 → 调用工具 → 读取 observation → 给出答案。

这样做有三重考量：

1. **信号纯净**：训练信号只包含 r_tool 和 r_answer 两个维度，模型不需要同时处理记忆的忠实度、覆盖率和长度权衡，学习目标明确。
2. **数据效率**：每个子问题独立采样，同样的 token 预算下能收集更多独立的训练样本（不会因为子问题链的失败级联浪费 token）。
3. **模块化验证**：如果工具使用能力没有提升，问题可以准确定位到 Phase 1 的 rollouter 或 reward 设计，而不是被 Phase 2 的记忆信号干扰诊断。

Phase 1 并非"不处理跨子问题依赖"——实际上，本 benchmark 中约 90% 的子问题是自包含的（问题文本和 related_tables 包含了回答所需的全部信息）。对于这 90% 的子问题，Phase 1 的独立训练已经足够。

### 4.3 Phase 2：完整对话训练（工具 + 答案 + 记忆）

Phase 2 将子问题串联为完整对话，模型在每个子问题回答后自主生成 `<memory>` 区块，该记忆直接传递给下一个子问题。不做任何验证器修正——模型需要从 reward 信号中自己学会"写什么记忆对后续有用"。

此时训练信号扩展到三个维度：r_tool（工具效率）、r_answer（答案质量）、r_memory（记忆质量）。这三个信号在实际训练中互相约束：如果记忆编造了数据（F_i 低），后续工具调用可能因表格中的矛盾数据获得低 r_tool，答案也因缺少证据支撑获得低 r_answer。反之，一份精确实用的记忆能减少后续子问题的工具调用次数，帮助模型更快地给出正确答案。

Phase 2 的训练起点是 Phase 1 的 checkpoint——模型已经学会了"如何用工具回答一个子问题"，Phase 2 只需微调"何时信任记忆、何时重新查表、记忆该写什么"。

### 4.4 Phase 3：反事实记忆价值校准（可选增强）

Phase 2 的记忆奖励建立在代理指标（忠实度 + FDC 覆盖 + 压缩）的基础上。但代理指标和真实效用之间可能存在偏差：一份记忆可能忠实但不包含后续真正需要的信息；也可能看似覆盖率低但恰好包含了关键数据。

Phase 3 通过配对对照实验直接测量记忆的边际效用。对于每个有拓扑依赖的记忆边界（子问题 i 为子问题 j 提供了信息），运行两条续跑：

- **续跑 A**：使用模型生成的 $M_i^{gen}$ 回答子问题 j，得到 $r_{ans}^{gen}$
- **续跑 B**：使用上一轮记忆 $M_{i-1}$ 回答子问题 j，得到 $r_{ans}^{prev}$

$$\Delta U_i = r_{ans}^{gen} - r_{ans}^{prev}$$

$\Delta U_i > 0$ 说明新记忆确实改善了后续答案，$\Delta U_i < 0$ 说明新记忆比旧记忆更有害（可能写入了错误信息）。

最终记忆奖励在 Phase 2 基础上加上反事实调整：

$$r_{mem}^{final} = r_{mem} + \lambda_{cf} \cdot (\mathbb{1}[F_i \geq \tau_f] \cdot [\Delta U_i]_+ + [\Delta U_i]_-)$$

核心设计意图：正向 $\Delta U$ 需要忠实度门控（不忠实的记忆即使碰巧有用也不奖励），负向 $\Delta U$ 始终计入（有害的记忆无论忠实与否都应惩罚）。

反事实续跑成本高（每条边界需额外运行两次对话），因此只稀疏触发（默认 25% 的边界），并使用低温度（0.3）保证续跑的确定性。Phase 3 标注为可选增强——其价值在"子问题间有硬性值传递依赖"的 benchmark 中更大，在当前以自包含子问题为主的 benchmark 中作为 Phase 2 的校准补充。

## 5. 设计决策总结

| 决策 | 选择 | 理由 |
|------|------|------|
| 优化算法 | GRPO（组相对优势） | 不需要 critic，减少计算开销和训练不稳定性 |
| Advantage 计算 | 组内 z-score 归一化 | 相同 prompt 的 K 条轨迹直接对比，无需估计 V(s) |
| Token 粒度 | 按消息类型分 advantage，assistant 可训练 | 精确控制哪些 token 参与梯度更新 |
| 证据验证 | 纯规则（6 维度） | 高频调用（每步工具），LLM 延迟和成本不可接受 |
| 目标证据/依赖构建 | 规则优先 + LLM 补充 | 规则保证覆盖率，LLM 补全语义标注 |
| 训练策略 | 课程学习（Phase 1 → 2 → 3） | 信号由简到繁，每个阶段在前一阶段 checkpoint 上微调 |
| Memory 传递 | 模型原始输出，不做修正 | 让 reward 信号直接驱动记忆质量，不引入外部校正 |
| 反事实评估 | 稀疏采样 + 配对续跑 | 在不过度增加计算量的前提下校准记忆奖励 |

## 6. 与标准 RLHF / PPO 的关系

TEMPO-RL 不是 RLHF 的替代方案，而是面向**可验证的工具交互场景**的针对性设计。与传统 RLHF 的关键区别：

- **不需要人类偏好数据**：奖励信号来自可自动验证的证据匹配，而非人类标注的偏好对比
- **不需要 reward model**：奖励函数是确定性的证据匹配计算，不存在 reward hacking 的空间（证据是 benchmark 预先定义好的客观事实）
- **不需要 critic**：GRPO 的组内对比替代了价值函数估计，减少了模型参数和训练步骤
- **分段 token mask**：不是所有 token 都参与训练，只优化模型生成的 decision token

这些设计使 TEMPO-RL 特别适合"有明确评判标准、涉及多步工具调用、需要跨轮次记忆管理"的表格智能体场景。在概念上，它可以被理解为一种**面向 tool-augmented agent 的可验证奖励 RL 框架**。
